## 1. 最终目标

基于 `docs/Top-Seed-官网产品-PRD.md`，完成 Top Seed 公开网站的产品、设计、数据和工程实现。

最终网站必须做到：

1. Seed、Series A、Series B、Series C 各展示 Top 50，共 200 家；
2. 公开说明每个 Top 50 来自多少家完成资格审核的候选公司；
3. 覆盖 AI 软件、硬件、芯片、算力、机器人、自动驾驶、AI 科学和软硬一体公司；
4. Ranking 是首页，Explore 能力位于 Ranking 内；
5. 顶部只有 Top Seed 品牌标志，以及 Ranking、Signals、Search 三个导航操作；
6. Company 由 Ranking、Signals 和 Search 进入，不作为一级导航；
7. Compare、Subscribe、付费入口和 Series D+ 全部删除；
8. Signals 持续承接融资以外的产品、客户、创始人、团队、技术、制造、部署和监管信息；
9. 事实、公司自述、Top Seed 判断和未核实信息表达清楚，并可以回到原始来源；
10. 网站形成明确、精细、可记忆的品牌与动效语言，不能呈现常见模板或粗糙的 vibe coding 质感。

“完成”不是代码能够运行，而是产品、视觉、数据、交互、响应式、无障碍和真实浏览器验证全部达到本文评分门槛。

## 3. 模型与团队配置

主 Agent 是团队负责人，只负责拆分、协调、决策记录、验收和整合。团队负责人不与执行 Agent 抢同一文件。

先加载可用的 teammode 规则并选择一种团队传输方式：优先使用原生 MultiAgentV2；不可用时使用 Codex App threads。团队生命周期内不得混用两种方式。使用 teammode 时通过其脚本初始化和维护团队状态，不手写团队状态文件。每个 Agent 使用唯一任务名和清楚的对话标题。

### 3.1 Sol 监督

所有监督 Agent 使用：

- model：`gpt-5.6-sol`
- reasoning effort：`high`
- 工作方式：只读评审，不直接修改产品文件

至少建立两个互相独立的 Sol：

1. `sol_supervisor`：持续监督 PRD 覆盖、产品决策、信息架构、设计方向和各执行单元；
2. `sol_final_gate`：不参与日常实现，只在候选最终版本上做独立终审，防止同一监督者既提要求又批准自己的要求。

Sol 的每项结论必须给出：证据、具体问题、影响、责任 Agent、修改要求和分数。没有文件、截图、真实页面、测试或来源作为证据的评分无效。

## 4. GO MODE 工作规则

1. 先核实，再修改。能够从代码、运行页面、数据和公开来源确认的问题，不反问用户。
2. 采用可撤销的合理默认值继续执行。只有缺少权限、需要不可逆操作，或不同选择会实质改变产品定位时才暂停询问。
3. 不伪造公司、融资、客户、性能、候选池数量、Signals、实时更新或历史名次。
4. 没有公开观察到的信息写 `Not publicly observed`，不能根据相邻信息补齐。
5. 候选池数字必须来自同一截止日、同一资格规则下的实际审核与去重记录。
6. 排名方法未最终确认前保留 `Editorial beta`，不展示伪精确分数。
7. Ranking 采用版本化发布；Signals 可以在审核后持续更新。未确定正式频率前不要在页面承诺固定周期。
8. 当前代码中可复用的路由、数据校验、组件和样式先复用。不要增加没有实际需要的框架、依赖或抽象。
9. 不用截图覆盖、图片模拟界面、大段硬编码位置或假数据完成视觉效果。
10. 保留用户已有修改，不回滚无关文件，不使用破坏性 Git 命令。
11. 每个执行 Agent 完成后先自检；Sol 再独立评分。执行者不能批准自己的交付。
12. 评分未达标就返回原责任 Agent 修复。连续两次没有实质改进时，Sol 必须重写任务边界或交给另一名 Luna Max。
13. 每次返工只重验受影响部分；候选最终版本只做一次完整收口验证。修复最终验证发现的问题后，再重跑受影响检查和一次新的最终验证。

## 5. 执行顺序

### Wave 0：基线和任务合同

并行完成：

- `luna_baseline` 运行现有网站，记录真实页面、所有路由、已有数据量、已知测试和当前视觉问题；
- `sol_supervisor` 将 PRD 转成去重后的实现清单、文件所有权和验收矩阵；
- 主 Agent 建立唯一问题清单和 Agent 责任表。

本阶段通过后才允许修改生产代码。

### Wave 1：并行研究和方向探索

同时启动：

- 三个视觉方向 Luna；
- Seed、A、B、C 四个数据研究 Luna；
- `luna_app_structure` 研究当前结构并提出最小改造方案。

视觉方向必须显示至少 Ranking、Company、Signals 三个真实页面状态，以及桌面和移动端关键画面。只提交 moodboard、色板或首页 hero 不算完整方向。

数据研究必须保留每条关键事实的来源、发布日期、事件日期、来源关系和证据状态。PR 稿与独立报道不能混为同一种证据。

Wave 1 结束时，由 `sol_supervisor` 给每个方向评分，选择一个视觉方向，并确认生产实现所需的数据合同。没有方向达到最低分时继续探索，不得为了赶进度随便选一个。

### Wave 2：功能实现

按已确认的文件所有权并行完成：

- 页面结构、URL 和状态恢复；
- Ranking 与四阶段 Top 50；
- Company、Signals 和全局 Search；
- Methodology、Evidence Policy、Corrections 和 About；
- 四轮数据整合、实体去重和一致性校验。

如果当前实现集中在少数单体文件中，先由 `luna_app_structure` 完成最小必要拆分，再启动不会互相覆盖的执行任务。不要让多个 Agent 在同一单体文件上同时提交冲突修改。

### Wave 3：视觉整合与动效

`luna_design_integrator` 只实现 Sol 选中的方向，统一：

- 字体、字号、行高和内容宽度；
- 色彩、对比度、间距、网格和响应式断点；
- 按钮、链接、筛选器、榜单条目、Signal、来源和状态组件；
- Ranking、Company、Signals、Search 和信任页面；
- hover、focus、pressed、disabled、empty、loading 和 error；
- 页面与状态之间有意义的动效；
- `prefers-reduced-motion` 下的等价体验。

### Wave 4：真实 QA 和返工

`luna_qa` 必须在真实浏览器中完成桌面、平板和移动端场景；自动测试不能代替视觉检查，静态截图也不能代替交互验证。

Sol 根据 QA 证据出具问题清单和分数。所有确认问题回到原责任 Agent 修复，直到问题清零。

### Wave 5：独立终审

`sol_final_gate` 从零开始阅读 PRD、查看最终代码、运行网站并检查证据。它不能继承 `sol_supervisor` 的通过结论，也不能因为执行时间长而降低评分。

只有终审达到本文停止条件，主 Agent 才能宣布完成并归档团队。
