# connectto｜产品结论日志

# 2026-08-09｜Connector 改为授权范围内的多方协商 Agent

## 1. Connection 由多方持续协商形成

第一阶段不再采用“AI 推荐、人来审批”的工作方式。每位参与者分别拥有自己的意图、条件、私人判断和披露边界；Connector 通过持续试探、追问和协调，让一次 Connection 逐步形成。

Connector 不把其他参与者当成主用户可以直接调用的关系资源，也不以生成一条建议或一张卡片作为完成。真实交流开始、条件被接受或各方明确结束，才构成可回流的结果。

## 2. Connector 按用户设定的授权等级工作

授权分为三档：

1. **请求批准**：每次对外行动前询问；
2. **在我的边界内推进**：在已确认的意图、关系范围和披露边界内主动试探、追问和协调；
3. **自主推进**：在用户设定的长期边界内拥有更高自主权。

新用户默认从“请求批准”开始。用户可以设置默认档位，也可以针对某个当前意图随时调整、降级或暂停；系统不得自行提高授权等级。

Connector 只在需要新的个人判断、扩大披露范围或形成新承诺时回来询问本人。未经允许的私人信息、法律或财务承诺、代表本人的价值判断，以及超出指定关系范围的联系，不因授权等级提高而自动放开。

## 3. 未注册参与者通过临时 Connector 加入

主用户拥有长期 Connector。尚未注册的参与者通过本次 Connection 专属的临时 Connector 参与，不需要先创建账户。

临时 Connector 只知道完成本次协商所需的最小上下文，私下询问当事人的意图、条件和披露许可，只分享本人明确允许使用的内容。当事人之后注册时，才可以在身份确认和本人同意后把本次记录并入长期 Connector。

## 4. 不设置统一的共享层

前端不要求参与者共同维护一份共享页面。系统中的每条事实、判断、条件和承诺分别记录来源、可见对象、允许用途和授权状态；Connector 只组合所有相关参与者都允许用于本次 Connection 的最小上下文。

用户只需要知道某项内容谁能看见、将用于什么，以及是否已经允许对外使用。

## 5. 第一次使用用一句话启动

用户用一句文字或语音说明最近想促成什么。Connector 根据已有上下文理解意图，最多追问一两个会改变行动的问题，再用人话说明可以联系谁、可以披露什么，以及何时会回来询问本人，目标是在一分钟内开始工作。

Current Focus、关系范围和权限对象属于系统内部结构，不做成首次使用时的配置表。用户完成一次真实使用后，可以把本次授权保存成默认设置。

## 6. connectto 承接完整关系工作流

connectto 不能只是后台运行、偶尔通知用户的状态工具。第一阶段需要进入创业者和独立 BD 的主要工作流，承接：**会前准备 → 真实交流 → 记录发生了什么 → 持续协调和推进 → 为下一次交流做准备。**

用户持续回来，是因为重要关系工作本来就在 connectto 中发生，而不是为了监督 AI 或审批建议。页面布局、信息架构、视觉设计和 App 的最终形态仍未确定，由产品同事继续定义。

## 7. 本条取代和降级的旧结论

本条取代此前“所有对外表达、披露和发送都由用户逐次确认”“Connector 负责推荐、用户负责审批”的结论。首页建议、人物页、Connection Card 和“第一阶段只打磨手机 App”降为待验证的产品假设，不再作为研发开工依据。

# 2026-08-08｜第一阶段定义为完整个人关系 Agent

## 1. 第一阶段交付一套可以持续使用的产品

connectto 第一阶段只服务创业者和独立 BD。用户可以从一次重要交流或一件当前事项开始，产品同时提供自我 Profile、Living Profile、关系记忆、Current Focus、Open Loops、Connector、Connection 和结果回流。

研发可以分顺序实现，但产品范围和用户心智不再拆成 V1A、V1B 或其他内部阶段。

## 2. 两个入口进入同一条关系闭环

- **重要交流刚结束：** 用户输入文字、口述复盘或导入外部录音。connectto 提取主要人物、关键信息、承诺、Open Loops 和人物线索，更新关系理解，并在合适的时机帮助用户继续。
- **当前事项已经出现：** 用户说出正在推进的融资、销售、招聘、合作或其他事项。connectto 结合人物、关系、当前意图和可信路径寻找候选人，帮助用户发起自我介绍、第三方介绍或已有关系复联。

两种入口共用同一套人物与关系上下文。一次行动的结果继续更新后续判断，并帮助用户发现下一次值得发生的连接。

## 3. Connector 和下一次机会属于第一阶段

Connector 不只响应用户找人，也会在证据充分时主动提出复联或新连接机会。所有对外表达、披露和发送仍由用户确认；接收者无需注册即可查看和回应受控的 Connection。

第一阶段是否成立，最终看用户是否完成“输入或表达当前事项—理解人物与关系—采取真实行动—结果回流—再次使用”，以及本次积累是否帮助产生下一次连接。

## 4. 本条取代的旧结论

本条取代本页此前把录音、关系记忆、Open Loops、已有关系复联或主动 Connector 放入后续阶段的结论，也取代 YC 评审中用 V1A、V1B 决定第一阶段产品范围的安排。V1A、V1B 仍可作为历史验证建议参考，不再决定第一阶段向用户提供哪些能力。

# 2026-08-02｜第一版改为一体化连接闭环

## 1. 第一版不再划分内部阶段

connectto 第一版统一为一条不断增强的闭环：**连接意图 → 按需理解人物 → 定向介绍 → 双方同意 → 真实交流 → 结果沉淀 → 发现下一次机会 → 再次连接。**

Profile、人物页和 Connector 从第一次使用开始共同存在，并随可信上下文逐渐增强。研发可以有实现顺序，但产品定义和用户心智不按阶段拆开。

## 2. 首页、人物页与 Card 各自承担一个任务

- 首页承接连接意图、当前需求与 Connector 建议；
- 人物页呈现 Living Profile 当前理解、相关经历、少量关系线索、来源和修正入口；
- Connection Card 是针对具体接收者与目的生成的一次受控表达。

人物页不成为 CRM 档案，关系线索不形成独立任务中心。

## 3. Connector 属于第一版，但根据证据渐进出现

Connector 先响应用户明确意图。只有人物匹配、时机、双方价值和可信路径能够被解释时，才主动提出连接或复联机会。普通机会进入首页；只有明确且正在消失的机会窗口才推送。新用户上下文不足时不会被强行推荐。

## 4. 第一版用“下一次连接”证明长期价值

第一张卡片促成交流只是闭环前半段。第一版最终成立，需要一次连接沉淀的可信理解帮助用户找到或发现下一次连接或复联机会，并被用户采纳，重新进入 Connection 链路。

# 2026-08-02｜第一阶段转向新连接闭环

本轮重新确认了“让关系活起来”与“分享漂亮 Profile”之间缺失的产品机制。第一阶段的核心从资料管理或交流记录，收束为一次有具体理由、经双方同意并真实开始的新连接。

本条取代此前把“最小 Profile—真实交流记录—关系动量 push”作为第一阶段主链的定义；录音、关系记忆、Open Loops 与已有关系复联继续保留在后续阶段。

## 1. Connection 是核心对象

- **Profile**：私人、持续、多来源的人物上下文底座；
- **Connection**：谁与谁、为什么此刻值得认识的一次具体连接事件；
- **Connection Card**：Profile 针对具体接收者和目的形成的一次表达；
- **Agent**：先响应用户意图，再从真实连接与结果中学习并逐渐主动。

漂亮、简洁和顺滑是卡片的必要体验条件，但连接理由、许可和现实结果才是产品价值。

## 2. 自我介绍与第三方介绍共用一条链路

一次 Connection 统一包含：

1. 发起人；
2. 被介绍者；
3. 接收者；
4. 本次目的。

场景化自我介绍是“发起人等于被介绍者”的特殊情况。第三方介绍则由发起人以自己的判断为被介绍者背书。

## 3. 具体对象优先，场景只是视角

Connection Card 默认针对具体接收者生成。投资、合作、招聘、朋友介绍等场景只帮助 Agent 理解本次目的，不形成固定模板或永久人物标签。

生成依据是被介绍者上下文、接收者上下文、发起人判断与本次目的的交集。

## 4. Profile 按连接即时建立

用户自己的 Profile 可以从本人授权或主动提供的职业资料、主页、简历、链接和直接表达中形成。

其他人物只在一次真实连接需要他们时，聚合联系人、用户提供的链接、已有记录和可使用的公开资料。connectto 只追问会改变介绍质量的缺失信息。

第一阶段保留多来源结构，但不以搬入完整关系库或抓取完整 LinkedIn 网络作为前提。

## 5. 第三方介绍由介绍人背书，本人先同意

当被介绍者尚未加入 connectto 时：

- 卡片明确显示“由谁介绍”；
- 介绍理由代表介绍人的判断；
- 可核实事实保留来源；
- AI 只负责检索、选择、压缩和组织；
- 被介绍者先确认愿意参与，并可以修正涉及自己的事实；
- 获得同意后才向接收者分享。

被介绍者之后可以认领或补充自己的 Profile，但认领不是介绍人形成草稿的前提。

## 6. Card 属于一次连接，不是永久公开主页

每次 Connection 使用独立、不可公开检索、可以撤回的免登录私密链接。

卡片只展示本次连接需要、即使误转发也不会造成明显伤害的信息。私人笔记、推测、完整关系历史和联系方式不会在双方同意前公开。

## 7. 双方同意并开始交流才算成立

第三方介绍先获得被介绍者同意，再向接收者发出 Connection Card。接收者可以表达“愿意认识”或“暂不合适”。

双方愿意后，由介绍人在微信、邮件等现有工具中拉起交流。卡片生成、发送或打开只是中间信号；真实交流开始才代表 Connection 成立。

接受、拒绝和后续结果都回到人物上下文与 Agent 判断。

## 8. Agent 从用户发起逐渐走向主动

冷启动阶段由用户用文字或语音说出一次真实连接。每次选择、编辑、许可、接受、拒绝和实际结果都成为 Agent 学习连接判断的样本。

只有当人物匹配、时机、双方价值和可信路径都能被解释时，Agent 才建议新的连接机会；是否发起、披露和发送继续由用户决定。

# 2026-08-02｜第一阶段收束：资料冷启动与关系动量

## 1. Profile 建立与真实交流不再绑定先后

自我 Profile 可以先从用户授权或主动提供的 LinkedIn、个人主页、简历等现有职业资料生成草稿，也可以先从文字、语音或第一场真实交流开始。信息先到或后到不决定重要性；所有内容保留来源、时间和适用范围，之后到达的交流用于校正和更新。

稳定的公开身份主要由现有资料提供；当前事项、需求、能力和私人关系上下文主要从用户表达与真实交流中形成。用户只确认会影响对外表达和行动的关键内容。

## 2. 冷启动是入口策略，不改变产品本质流程

默认冷启动只要求一个可用资料源，生成“这是不是你”的自我 Profile 草稿；用户可以修正后继续，也可以跳过导入。LinkedIn 是候选来源之一，不成为唯一依赖。

LinkedIn 官方接口允许在授权下读取当前登录成员资料，但读取和保存其他成员资料受到更严格限制，因此他人 Profile 仍以用户提供的联系人、资料链接、有来源的公开信息和真实交流共同形成。[LinkedIn Profile API 说明](https://learn.microsoft.com/en-us/linkedin/shared/integrations/people/profile-api)

## 3. 第一阶段收成“一人、一源、一段关系、一次主动促成”

- **一人**：Alex 作为首个独立用户；
- **一源**：一个已有职业资料源生成自我 Profile 草稿；
- **一段关系**：一场真实交流建立一个主要人物的私人关系上下文；
- **一次主动促成**：connectto 在没有固定提醒作为唯一依据时，基于关系动量提出一次值得继续的连接。

分享继续承担对外表达与自然增长。当前事项找人和更多跨人物匹配建立在这条最小闭环已经成立之后。

## 4. Connector 从时间提醒转向关系动量

“下次再聊”“下来看看”“下周见”通常表达继续意愿，不自动等于真实日程。connectto 区分硬承诺、软继续意愿、礼貌收尾和真正结束；时间只是证据，关系是否仍有互相兴趣、是否正在冷却、是否出现新的连接理由，才共同决定何时 push。

Connector 对本来值得继续、却正因缺少契机而冷却的关系保持主动。每次 push 都说明为什么是这个人、为什么是现在、什么可能被错过，以及最低摩擦的继续方式。用户的行动、忽略、延后和拒绝继续校正之后的判断。

## 5. 他人 Profile 是私人关系对象，不自动成为平台用户

Alex 记录与 Nicole 的交流后，Nicole 可以拥有公开身份候选和只属于 Alex 的私人关系上下文，但不会因此自动注册为 connectto 用户。公开身份与私人关系持续分层；未来本人加入时，再在授权和身份确认后建立对应关系。

# 2026-08-02｜从交流执行到主动 Connector

## 1. 目标用户从具体工作事件定义

创业者同时进行客户交流、销售、招聘、融资和合作，一次一对一交流既会产生眼前行动，也可能改变产品、目标客户和下一条连接路径。独立 BD 一边交付当前事项，一边发现和推进未来合作，核心工作是判断人与需求如何匹配，并用个人信任促成连接。

connectto 聚焦三个真实时刻：交流刚结束；当前事项已经出现但人选或路径不确定；新的互补价值出现但用户尚未主动搜索。[创业者一手案例](https://www.kracov.co/writing/founder-sales) · [独立从业者工作案例](https://www.cipd.org/en/the-people-profession/meet-the-people-professionals/day-in-the-life-consultancy-independent/)

## 2. 短期执行层采用成熟路径

对话整理、行动项生成和提醒执行已经有成熟产品范式。第一阶段在这一层集中优化准确、关键确认和低摩擦，让一次交流产生的明确行动顺利落地，并把真实结果写回关系。

To-Do 和提醒是关系数据进入现实的执行层。connectto 的差异化来自跨互动的长期理解、当前事项找人和新的连接发现。

## 3. 长期核心转向两类 Connector

- **意图驱动**：用户清楚现在要推进什么，但不知道该找谁或经由谁连接；connectto 给出候选人、连接路径和相关依据；
- **机会驱动**：人物近况、当前意图或能力互补使一条连接重新产生价值；connectto 解释为什么是现在、双方分别获得什么、信任路径与许可条件，再由用户决定是否行动。

明确承诺继续进入成熟行动链路，但不拥有天然更高的 Connector 优先级。关系动量、当前意图和新的互补价值共同进入“候选—确认—行动—结果回流”的闭环。

## 4. 产品哲思结合个人利益与共同创造

关系不是中心平台拥有的流量资产，而是个人拥有的信任与协作能力。connectto 将关系上下文、介绍决定、代理权限和连接结果交还个人；谁促成连接及结果如何，也回到个人长期拥有的关系历史。

个人掌握自己的关系与代理权，是可信协作的前提。连接建议同时考虑双方价值、信任路径、时机与许可，使关系可以从个人收益继续走向共同创造。

## 5. User Story 按证据状态管理

公开的一手案例用于建立初步角色理解；“事情已经出现，但人选不确定”目前作为核心待验证假设。第一轮通过 5 位创业者和 5 位独立 BD 的近期事件复盘与两周记录验证，不把假设性回答写成用户事实。

研究复盘三类实际事件：过去 14 天的重要一对一交流、一次当前事项找人的真实过程、一次真实介绍及最终结果。只有反复出现且能展示过程与结果的事件进入核心 User Story。

# 2026-08-02｜关系科技边界与第一阶段校准

## 1. connectto 的产品承诺是减少本可避免的关系流失

技术可以提高可触达性、保存上下文并降低行动摩擦；亲密、信任和关系是否继续，仍由真实的人际互动产生。

connectto 优先帮助那些用户本来在意、却可能因忙碌、遗忘、上下文丢失和承诺遗漏而中断的关系。第一阶段的承诺确定为：帮助用户留下真正重要的内容、兑现承诺，并在下一次真实联系时更好地出现。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md) · [长期愿景](Agent-Native-时代的个人身份与协商基础设施.md)

## 2. Profile 是指向真人的可信记忆入口

Profile 保存当前身份、相识背景、历次互动、承诺、结果和来源，帮助用户在下一次交流前恢复上下文。它始终保留时间、来源和可更正性，每一次新的真实交流都可以修正此前理解。

Profile 的产品价值，是让用户更有准备地重新面对这个人，而不是让资料代替人与人的重新理解。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md) · [长期愿景](Agent-Native-时代的个人身份与协商基础设施.md)

## 3. Connector 和 Agent 在真实连接发生时把关系交还用户

Connector 每次出现都需要说明为什么是现在、上次发生了什么、谁需要做什么，以及用户可以如何选择。Agent 可以恢复上下文、准备沟通和材料，并在授权范围内执行低风险行动。

当用户开始与对方真实交流时，connectto 将判断和表达交还本人；系统的价值是帮助用户更有准备地出现，而不是长期占据双方之间的位置。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md) · [后续能力演进](后续能力演进.md) · [长期愿景](Agent-Native-时代的个人身份与协商基础设施.md)

## 4. 产品结构留在后台，前台围绕真实交流时刻产生即时价值

个人关系产品可以在后台高度结构化，但用户价值不能建立在持续维护一套关系数据库上。第一阶段以轻量自我 Profile、文字或语音记录、外部录音导入和受控分享形成即时价值；用户第一次处理关系时，立即得到人物理解、双方承诺、下一步和重新出现条件。

产品同时验证“录入或导入—理解—确认—人物呈现—分享”的即时链路，以及“重新出现—行动—结果回流”的持续链路。更动态的身份理解、Agent 行动和网络能力再从真实使用中深化。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md) · [后续能力演进](后续能力演进.md)

## 5. 第一阶段用真实关系行为判断是否成立

第一阶段优先观察：

1. 首次文字、语音或外部录音输入，是否抓住这次交流真正重要的部分；
2. 用户是否愿意主动记录另一场交流；
3. connectto 是否在有明确理由时正确恢复上下文；
4. 用户是否因此以自己的方式完成、延后或停止一项真实行动；
5. 结果是否回到关系记忆并改变后续判断。

联系人、Profile 和提醒数量只作为诊断信号。产品最终要证明的是用户能否更可靠地出现、兑现承诺并保持关系连续。

# 2026-08-01｜第一阶段产品方向

## 1. 第一阶段先完成个人关系闭环

connectto 的第一阶段，是让一个人独立使用也能持续获得价值的职业关系产品。用户在一次重要交流之后留下信息，connectto 形成关系记忆，并在之后帮助用户继续推进。

关系由人物、相识背景、历次互动、双方承诺、待继续事项和真实结果共同构成。第一阶段的核心闭环是：**记录—重新出现—行动—结果回流**。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md)

## 2. 第一轮聚焦创业者与独立 BD

第一轮目标用户是创业者和拥有个人关系资产的独立 BD，核心场景是一场值得记住或继续推进的一对一职业交流。

产品首先帮助他们记住对方是谁、为什么认识、双方答应了什么，以及接下来为什么和什么时候值得继续。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md)

## 3. 文字、会后口述和外部录音是输入，关系 Profile 是当前结果

用户可以直接打字、口述复盘，或导入外部完整录音，并补充联系人、文字或链接。语音先转成可编辑文本；connectto 在用户修正后识别人和说话人，整理本次互动、相识背景、双方关注、承诺、待继续事项和相关资料。

关系 Profile 是一份会持续更新的当前简报，优先回答四件事：

1. 他现在是谁；
2. 我们为什么认识；
3. 最近发生了什么；
4. 现在有什么待继续事项。

历次互动和身份变化继续保留，需要追溯时再展开。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md)

## 4. 第一次使用必须立即形成可见结果

用户先用一段文字或语音形成最小自我 Profile 和第一张分享卡，不需要填写完整简历。处理第一场关系时，只需要一个主要人物和一段互动；用户输入或导入后，应立刻得到人物锚点、这次最值得记住的、下一步和已记住的新信息。

第一次价值是“我可以被清楚地表达，这次交流也能被处理妥当”；持续价值来自 connectto 之后在正确时机带回上下文，并把行动结果继续写回这段关系。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md)

## 5. Open Loops 是第一阶段的行动核心

Open Loops 至少区分五种状态：

- 我需要做；
- 等待对方；
- 双方共同继续；
- 当前没有下一步；
- 已经结束。

Threads 在第一阶段只负责说明“这段关系与用户正在推进的哪件事有关”，让人物、承诺和后续行动拥有共同上下文。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md)

## 6. Connector 采用关系动量优先

第一阶段不再把明确日期和用户设置的提醒作为唯一可靠触发。connectto 区分硬承诺、软继续意愿、礼貌收尾和真正结束，并综合未完成的话题、双方兴趣、人物近况、当前事项、沉默时间和用户反馈判断关系动量。

当一段仍有价值的关系正在因缺少契机而冷却，或新的连接理由出现时，Connector 可以主动 push。每次出现说明为什么是现在、什么可能被错过、最自然的继续方式是什么，并允许用户行动、修改、延后、忽略或让关系沉默。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md)

## 7. connectto 是个人 Agent 的第一块关系能力

产品优先级仍然是 connectto。第一阶段先形成一组相互连接的垂直能力：从一个现有资料源生成最小自我 Profile，理解并记住一段关系，受控分享，基于关系动量主动促成，并吸收用户反应与行动结果。

这些真实使用同时建立个人 Agent 所需的长期记忆、当前事项、触发条件、权限边界和结果反馈。connectto 的第一阶段就是个人 Agent 最先成立的关系与身份能力，更多通用行动能力再从真实使用中逐步形成。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md) · [后续能力演进](后续能力演进.md)

## 8. 一次记录围绕一个主要人物，其他人采用人物线索制

每次关系记录都以一个主要人物为中心，无论用户直接打字、口述复盘，还是导入完整录音，都持续积累用户与这个人的关系。

输入中可以同时提到交流涉及的其他人物。这些人物先作为附属于当前交流的人物线索被保留，之后可升级成独立关系；这条记录的主要关系始终属于本次交流的主要人物。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md)

## 9. 人物线索采用“身份关联—关系形成”两步机制

人物线索是一条关于某个人、带有交流来源的关系证据，而不是一个未完成的 Profile。connectto 先判断线索指向谁，再判断这个人是否已经成为用户可以直接行动和持续管理的关系对象。

身份不确定但暂时不影响行动时，线索继续保留；身份判断将影响提醒、关系建立或下一步行动时，用户只确认人物身份。独立关系形成后，此前线索作为关系建立前上下文继续保留。

人物身份、直接互动和间接提及保持区分，所有线索保留来源，身份关联可以更正或拆开。人物、来源交流、相关话题和承诺之间的联系持续保留，使 connectto 能够找回这段关系从哪里产生、为什么相关。

**已同步：** [第一版产品 PRD](第一版产品-PRD.md) · [后续能力演进](后续能力演进.md)

## 10. 长期愿景与产品成长主轴合并

connectto 的长期愿景，是成为 Agent-Native 世界中的个人身份与代理权基础设施。它从真实关系中获得可信上下文，逐渐理解并表达一个人，通过 Agent 帮助其行动，最终连接成由个人控制的协作与协商网络。

四部分的关系确定为：

- **关系**：真实数据入口和现实反馈层；
- **身份**：理解与表达；
- **Agent**：行动方式；
- **网络**：长期扩展。

Agent-Native 是长期终局，这四部分是 connectto 从第一阶段走向终局的产品主轴。第一阶段的“最小自我 Profile—录入或导入—理解与确认—人物呈现—受控分享”，加上“重新出现—行动—结果回流”，是整条主轴最薄的完整切片。

**已同步：** [长期愿景](Agent-Native-时代的个人身份与协商基础设施.md) · [第一版产品 PRD](第一版产品-PRD.md) · [后续能力演进](后续能力演进.md)

## 11. 第一阶段框架收束，转入真实使用验证

当前产品框架已经足以进入第一阶段，后续完善重点转为真实使用验证和闭环质量。V0 从用户授权或主动提供的一个现有职业资料源生成自我 Profile 草稿，同时支持文字、语音和外部录音；语音先转成可编辑文本。

第一阶段是否成立，看五个连续行为能否真实发生：

1. 用户无需从零填写即可得到可修正的自我 Profile 草稿；
2. 用户处理一场真实交流并形成一个主要人物的关系上下文；
3. connectto 至少一次不以固定提醒为唯一依据，基于关系动量主动 push；
4. 用户选择行动、修改、延后、忽略或让关系沉默；
5. 用户反应与真实结果回到关系记忆，并改变后续 Connector 判断。

长期产品主轴补齐三条一致性规则：

- **证据底座**：真实世界证据是 connectto 的数据底座；关系是第一阶段最重要、最自然的来源，长期还可以纳入用户明确表达的目标与意图、经授权的工具信号和行动结果；
- **个人控制**：来源、适用范围、披露、更正、删除、导出、授权、撤销与审计贯穿关系、身份、Agent 和网络；
- **结果回流**：关系、身份、Agent 和网络构成循环，协作结果持续回到关系、身份和下一步判断。

# 2026-08-02｜第一阶段入口、人物信息与分享链路

## 1. 第一阶段同时建立“我”和“他人”的信息底座

用户先从授权或主动提供的一个现有职业资料源生成最小自我 Profile 草稿，文字和语音用于补充当前事项、能力、需求与表达边界。

真实交流继续形成他人的关系 Profile。自我 Profile 服务身份表达，他人 Profile 服务私人关系理解；两者按各自来源和时间持续更新。

## 2. 人物信息同时区分私人底座与对外表达

自己的完整信息与“我的卡片”分开；他人的私人关系 Profile 与一次介绍卡片分开。

分享卡片是根据目的生成的表达，不是完整 Profile 的公开副本。私人判断、关系历史、原始录音和完整转写不会自动进入分享内容。

## 3. 文字与语音作为同一级入口

用户可以直接打字，也可以语音输入。语音先转成可编辑文本，用户可以按需修正；修改原文后，相关交流结果、Profile 更新、待继续事项和分享候选同步变化。

用户不需要逐字确认整篇转写，只确认会影响人物、说话人、承诺、自我 Profile、分享和后续行动的内容。

## 4. 外部完整录音进入第一阶段

用户可以从 Pocket、Plaud 等录音硬件或文件系统导入完整交流录音。外部录音先通过通用导入进入同一理解链路，并额外处理说话人、主要人物和承诺归属。

connectto 的二次分析围绕自己、他人、关系、承诺、人物线索、Profile 更新和分享表达，不重复停留在普通会议摘要。

## 5. 本次结果优先回答“最值得记住什么”

交流结果依次呈现人物锚点、这次最值得记住的、接下来、已记住的新信息、提到的其他人和原始依据。

本次结果表达这次新增了什么；自我 Profile 与他人的关系 Profile 表达截至现在的当前视图。

## 6. 分享是第一阶段增长入口

第一阶段支持分享自己的场景化卡片，也支持基于他人 Profile 生成带介绍理由的卡片。

卡片需要好看、信息层级清楚，生成、确认、分享和打开过程保持顺畅。用户在发送前确认全部可见内容；接收方能够快速理解这是谁、谁分享的、为什么相关以及如何继续。

增长来自分享本身为发送方和接收方创造价值。

# 2026-08-02｜产品呈现的前后台分层

## 1. 手机端围绕真实交流时刻

connectto 的主要使用表面应当轻量、直觉并适合在交流结束后立即拿起手机使用。用户从一次交流和当前意图开始，通过文字、语音或录音导入快速留下内容，再完成必要确认、查看结果和分享，而不是先进入联系人数据库。

## 2. 集中管理视图与即时体验分开

人物、关系、互动和待继续事项可以在系统内部高度结构化，但结构不应转化为用户持续维护字段、阶段和列表的负担。长期可以提供集中查看、检索和整理关系积累的管理视图，但它与手机端的即时体验承担不同任务，不能反过来决定手机端的产品形态。

## 3. 第一阶段只打磨手机 App

第一阶段所有核心闭环都必须在手机上独立完成，不以电脑端作为补充前提。手机端需要独立承接输入、确认、结果、人物 Profile、分享、重新出现和结果回流。

## 4. 第一阶段界面必须保持生命周期一致性

第一阶段的手机端呈现不能只是一个录入、摘要或联系人管理工具。它需要与长期“关系—身份—Agent—网络”共用同一产品骨架：第一阶段先承载关系记忆和最小身份，之后在同一主心智上增加理解、授权行动和网络协作，而不是进入下一阶段后推翻重做。
