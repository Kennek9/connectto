# 二、真实世界证据提供底座，关系首先建立可信上下文

真实世界证据是 connectto 的数据底座。第一版从一次连接意图、介绍人的判断、双方许可和实际结果形成第一批关系证据；同一条闭环继续吸收持续互动、承诺、行动与关系变化。长期还可以纳入用户明确表达的目标与意图、经授权进入的日历、任务和沟通信号，以及 Agent 行动后的现实结果。所有信息都需要保留来源、发生场景和适用范围，公开变化也只有在来源明确时才能成为补充证据。

身份不再只回答“我是谁”，还需要回答“我现在处于什么阶段、正在推进什么、希望发生什么，以及在这个场景里应该如何被理解”。它不要求用户先填写一份完整 Profile，而是从真实关系和现实结果中逐渐形成，再由用户决定如何表达。

| 长期能力 | 负责什么 |
| --- | --- |
| 关系上下文 | 保存发生过什么、与谁有关、谁承诺了什么、最后产生了什么结果 |
| 身份理解 | 持续理解用户的角色、阶段、当前关注、能力和边界 |
| 身份表达 | 按场景选择性表达用户愿意公开的身份、意图和可提供内容 |

> **connectto** 是一个由个人拥有的身份与代理权基础设施：它从真实关系中获得可信上下文，持续理解并表达一个人，并让 Agent 在用户授权下把这种理解转化为行动。
>

它最终需要回答六个问题：

1. 真实发生了什么，依据来自哪里？
2. 用户与谁有什么关系，这段关系如何形成和变化？
3. 用户现在是谁，正处于什么阶段并推进什么？
4. 在当前场景中，用户愿意如何被理解和表达？
5. Agent 可以代表用户准备、判断和行动到哪一步？
6. 外部的人、Agent 和机构可以如何与用户建立连接和协作？

<aside>
🌐

**产品哲思：个人拥有关系，共同创造价值**

关系不是中心平台拥有的流量资产，而是个人拥有的信任与协作能力。connectto 将关系上下文、介绍决定、代理权限和连接结果交还个人；在各方许可下，这些关系可以重新组合，帮助每个人获得更好的机会，也让更多人通过合作创造单点关系无法产生的共同价值。

</aside>

个人利益与共同体价值不是两条相反的路线。个人掌握自己的关系与代理权，是可信协作的前提；连接能否为双方创造价值，是网络长期成立的标准。

# 三、connectto 的长期骨架：关系—身份—Agent—网络

这四部分不是四个彼此独立的产品，而是一条持续获得现实反馈的循环。

| 部分 | 在系统中的作用 | 长期产生的价值 |
| --- | --- | --- |
| 关系 | 提供连接语境、许可和现实反馈 | 最先记录谁与谁为什么值得认识、谁促成、是否同意以及实际结果 |
| 身份 | 理解与表达层 | 形成持续更新的个人状态、意图和场景化表达 |
| Agent | 行动方式 | 恢复上下文、准备沟通、推进承诺，并在授权范围内执行 |
| 网络 | 长期扩展方式 | 让个人、Agent 和机构完成发现、匹配、协调与协商 |

<aside>
🔁

**长期闭环**

真实世界证据（关系优先） → 身份理解与表达 → Agent 行动 → 网络协作 → 现实结果回到关系、身份和下一步

</aside>

网络不是终点，现实结果也不是附属数据。每次行动与协作的结果都会反过来修正关系判断、个人理解、权限边界和下一次行动，使 connectto 对一个人的理解持续接受真实世界校正。

<aside>
🛡️

**贯穿四层的个人控制**

无论信息位于关系、身份、Agent 还是网络，用户都能知道来源和适用范围，决定什么保持私密、什么可以披露，能够更正、删除和导出，并能授权、撤销和审计 Agent 行动。个人控制不是第五层，而是四层共同遵守的规则。

</aside>

# 四、四类长期能力

## 4.1 Relationship Context｜关系上下文

关系层接收异步到达的多来源证据：用户授权或主动提供的职业资料、直接表达、真实交流、公开变化和行动结果。信息先到或后到不决定重要性；人物身份、公开资料、用户私人记忆和 AI 推断始终保留来源、时间与适用范围。

关系层继续保存相识场景、历次互动、直接与间接人物线索、硬承诺、软继续意愿和最终结果。一段关系可以获得动量、逐渐冷却、恢复或结束；旧历史不被新 Profile 覆盖。

connectto 因而能够解释“为什么认识、发生过什么、这段关系是否仍有继续价值、为什么现在值得行动，以及行动后发生了什么”。Profile 只是帮助用户重新面对真人的当前视图，每一次新的真实交流都可以修正此前理解。

## 4.2 Identity, State and Intent｜身份、状态与意图

这一层从长期关系和现实行动中理解：

- 用户正在扮演什么角色、处于什么阶段；
- 当前在寻找、推进或能够提供什么；
- 哪些信息可以公开，哪些只属于私人上下文；
- 面对不同的人和场景，应当表达哪个版本的自己；
- 当前意图的条件、边界和有效期限。

第一版按一次具体 Connection 即时聚合必要 Profile，并生成针对具体接收者的自我介绍或第三方介绍；更动态的身份、状态与意图继续从连续关系和现实行动中形成。身份底座必须足够轻，不成为获得连接价值之前的资料填写负担。

## 4.3 Permissioned Agency｜有边界的代理行动

Agent 负责把理解转化为行动：恢复上下文、准备沟通、整理材料、协调时间、推进承诺、筛选请求，并在用户明确授权的低风险范围内执行。

权限需要说明谁可以看到什么、哪些动作可以准备、哪些动作可以执行、何时必须交还本人、授权何时失效。关系建立、敏感信息、第三方介绍和重要承诺继续由本人决定。

Agent 的目标是让用户更有准备地出现。真实交流开始后，它将判断和表达交还用户，并在用户不再需要帮助时退到后台。

## 4.4 Collaboration and Negotiation Network｜协作与协商网络

当个人已经拥有可信上下文、可表达的身份和明确的代理边界后，connectto 才能把这些能力向外连接：

- 用户表达当前事项后，Agent 寻找合适的人与直接或间接连接路径；
- Agent 在人物近况、当前意图或能力互补发生变化时，发现新的连接候选；
- 每个候选解释时机依据、双方价值、信任路径和披露边界；
- 介绍在相关各方许可后发生；
- 谁促成了连接、各方采取了什么行动以及最终结果如何，回到各自拥有的关系上下文；
- 个人 Agent 与企业、机构和服务 Agent 协调低风险事项。

私人关系档案不因进入网络而公开。网络扩大的是个人可发起和参与的协作范围；关系上下文、介绍决定与连接结果继续由个人控制。

# 五、产品如何从一次连接走向持续协作

connectto 有四个进入时刻：

1. **一次新连接出现**：用户想把自己介绍给某个人，或认为另外两个人值得认识；
2. **连接之后发生真实交流**：新的理解、关系线索和结果继续进入人物上下文；
3. **已有关系值得重新出现**：用户提出当前需求，或系统发现新的连接理由；
4. **跨人物机会出现**：人物近况、当前意图或能力互补使两个人重新相关。

这些入口都进入同一条闭环：

1. 用户或 Connector 提出谁与谁为什么值得认识；
2. connectto 按需理解相关人物；
3. 系统形成面向具体接收者的受控表达；
4. 相关各方确认是否愿意以及可以披露什么；
5. 介绍人在现有工具中拉起真实交流，connectto 退到后台；
6. 接受、拒绝、交流和后续结果更新人物、关系、身份与 Agent 判断；
7. 证据充分后，Connector 找到或提出下一次连接机会，用户采纳后再次进入闭环。

Profile、人物页和 Connector 从第一次连接开始共同存在。它们的深度随真实使用增加，而不是作为相互割裂的产品阶段出现。

# 六、为什么从真实关系切入

| 入口条件 | 对产品的意义 |
| --- | --- |
| 单个用户立即有价值 | 一次自我介绍或第三方介绍即可产生结果，不等待对方安装 |
| 上下文接受现实校正 | 身份和判断建立在介绍选择、双方许可、真实交流与结果上，而不只依赖填写 |
| 每次使用可以复利 | 一次连接产生的理解，继续提高下一次人物检索、表达和建议质量 |
| 自然形成 Agent 内核 | 长期记忆、当前意图、触发条件、权限边界和结果反馈来自同一闭环 |
| 不依赖完整生态 | 单个用户即可建立最小上下文并受控分享；网络能力从真实连接中生长 |

connectto 当前要连续回答三个问题：

1. 我现在想认识或介绍某个人，怎样让对方快速理解为什么值得连接？
2. 每次真实交流产生的理解，怎样成为个人长期拥有、可修正的上下文？
3. 当新的需求或互补价值出现时，Connector 能否找到或提出一条对双方有价值、可解释且经过许可的连接？

# 七、能力如何逐步加深

| 能力方向 | 如何加深 | 持续产生的价值 |
| --- | --- | --- |
| 关系记忆 | 吸收更多真实交流、人物线索、关系线索、动量变化和最终结果 | 人物理解更连续，已有关系能在有真实理由时重新出现 |
| 机会发现 | 理解 Current Focus，检索人物与路径，结合时机和历史结果提出候选 | 用户有具体事项时找到合适的人，也能获得可信建议 |
| 有边界的 Agent | 在可查看、可撤销的权限内准备、协调并执行低风险行动 | 减少关系推进中的重复劳动，同时保留本人决定权 |
| 协作与协商网络 | 让个人、Agent 与机构在各方许可下完成发现、介绍、协调和协商 | 扩大个人可发起的协作范围，并把连接 credit 交还相关个人 |

> 演化原则：真实连接提供关系证据；连续关系让身份理解更可靠；身份和权限越清楚，Agent 才能承担更多行动；个人代理越可信，网络扩展才不会牺牲个人控制。

# 十、当前聚焦

长期愿景可以宏大，当前产品仍只围绕创业者和独立 BD 打磨一条最薄但完整的连接闭环：

1. 用户用文字或语音表达一次连接意图；
2. connectto 按当前对象和目的形成必要人物理解；
3. 自我介绍或第三方介绍经过相关本人确认，以私密 Connection Card 分享；
4. 双方愿意后在现有工具中开始真实交流；
5. 交流结果和后续输入继续更新 Living Profile；
6. 当用户提出新需求，或证据足以支持可信机会时，Connector 帮助发起下一次连接。

当前产品用这条闭环建立长期所需的关系证据、身份理解、许可边界和结果反馈。更多 Agent 行动与网络协作从真实使用中生长，不成为单个用户获得价值的前提。
