# 二、真实世界证据提供底座，关系首先建立可信上下文

真实世界证据是 connectto 的数据底座。第一版从用户表达的当前意图、真实交流、各方条件、披露许可和实际结果形成第一批关系证据；同一条闭环继续吸收持续互动、承诺、行动与关系变化。长期还可以纳入经授权进入的日历、任务和沟通信号，以及 Agent 行动后的现实结果。所有信息都需要保留来源、发生场景、可见对象和允许用途，公开变化也只有在来源明确时才能成为补充证据。

身份不再只回答“我是谁”，还需要回答“我现在处于什么阶段、正在推进什么、希望发生什么，以及在这个场景里应该如何被理解”。它不要求用户先填写一份完整 Profile，而是从真实关系和现实结果中逐渐形成，再由用户决定如何表达。

| 长期能力 | 负责什么 |
| --- | --- |
| 关系上下文 | 保存发生过什么、与谁有关、谁承诺了什么、最后产生了什么结果 |
| 身份理解 | 持续理解用户的角色、阶段、当前关注、能力和边界 |
| 身份表达 | 按场景选择性表达用户愿意公开的身份、意图和可提供内容 |

> **connectto** 是一个由个人拥有的身份与代理权基础设施：它从真实关系中获得可信上下文，持续理解并表达一个人，并让 Agent 在用户授权下把这种理解转化为行动。
>

它最终需要回答六个问题：

1. 真实发生了什么，依据来自哪里？
2. 用户与谁有什么关系，这段关系如何形成和变化？
3. 用户现在是谁，正处于什么阶段并推进什么？
4. 在当前场景中，用户愿意如何被理解和表达？
5. Agent 可以代表用户准备、判断和行动到哪一步？
6. 外部的人、Agent 和机构可以如何与用户建立连接和协作？

<aside>
🌐

**产品哲思：个人拥有关系，共同创造价值**

关系不是中心平台拥有的流量资产，而是个人拥有的信任与协作能力。connectto 将关系上下文、介绍决定、代理权限和连接结果交还个人；在各方许可下，这些关系可以重新组合，帮助每个人获得更好的机会，也让更多人通过合作创造单点关系无法产生的共同价值。

</aside>

个人利益与共同体价值不是两条相反的路线。个人掌握自己的关系与代理权，是可信协作的前提；连接能否为双方创造价值，是网络长期成立的标准。

# 三、connectto 的长期骨架：关系—身份—Agent—网络

这四部分不是四个彼此独立的产品，而是一条持续获得现实反馈的循环。

| 部分 | 在系统中的作用 | 长期产生的价值 |
| --- | --- | --- |
| 关系 | 提供连接语境、许可和现实反馈 | 最先记录谁与谁为什么值得认识、谁促成、是否同意以及实际结果 |
| 身份 | 理解与表达层 | 形成持续更新的个人状态、意图和场景化表达 |
| Agent | 行动方式 | 恢复上下文、准备沟通、推进承诺，并在授权范围内执行 |
| 网络 | 长期扩展方式 | 让个人、Agent 和机构完成发现、匹配、协调与协商 |

<aside>
🔁

**长期闭环**

真实世界证据（关系优先） → 身份理解与表达 → Agent 行动 → 网络协作 → 现实结果回到关系、身份和下一步

</aside>

网络不是终点，现实结果也不是附属数据。每次行动与协作的结果都会反过来修正关系判断、个人理解、权限边界和下一次行动，使 connectto 对一个人的理解持续接受真实世界校正。

<aside>
🛡️

**贯穿四层的个人控制**

无论信息位于关系、身份、Agent 还是网络，用户都能知道来源和适用范围，决定什么保持私密、什么可以披露，能够更正、删除和导出，并能授权、撤销和审计 Agent 行动。个人控制不是第五层，而是四层共同遵守的规则。

</aside>

# 四、四类长期能力

## 4.1 Relationship Context｜关系上下文

关系层接收异步到达的多来源证据：用户授权或主动提供的职业资料、直接表达、真实交流、公开变化和行动结果。信息先到或后到不决定重要性；人物身份、公开资料、用户私人记忆和 AI 推断始终保留来源、时间与适用范围。

关系层继续保存相识场景、历次互动、直接与间接人物线索、硬承诺、软继续意愿和最终结果。一段关系可以获得动量、逐渐冷却、恢复或结束；旧历史不被新 Profile 覆盖。

connectto 因而能够解释“为什么认识、发生过什么、这段关系是否仍有继续价值、为什么现在值得行动，以及行动后发生了什么”。Profile 只是帮助用户重新面对真人的当前视图，每一次新的真实交流都可以修正此前理解。

## 4.2 Identity, State and Intent｜身份、状态与意图

这一层从长期关系和现实行动中理解：

- 用户正在扮演什么角色、处于什么阶段；
- 当前在寻找、推进或能够提供什么；
- 哪些信息可以公开，哪些只属于私人上下文；
- 面对不同的人和场景，应当表达哪个版本的自己；
- 当前意图的条件、边界和有效期限。

第一版围绕一次具体 Connection 聚合必要人物与关系上下文，让各方分别表达意图、条件和披露边界；更动态的身份、状态与意图继续从连续关系和现实行动中形成。身份底座必须足够轻，不成为获得连接价值之前的资料填写负担。

## 4.3 Permissioned Agency｜有边界的代理行动

Agent 负责把理解转化为行动：恢复上下文、准备沟通、整理材料、协调时间、推进承诺、筛选请求，并在用户明确授权的低风险范围内执行。

权限需要说明谁可以看到什么、允许用于什么、哪些动作可以准备或执行、何时必须交还本人，以及授权何时失效。用户可以在“请求批准、在我的边界内推进、自主推进”之间设置默认方式，并针对具体意图调整、降级或暂停；系统不得自行提高授权等级。

在已经确认的意图、关系范围和披露边界内，Agent 可以主动试探、追问和协调。新的个人判断、扩大披露和重要承诺继续交还本人；未经允许的私人信息、法律或财务承诺、代表本人的价值判断和超出指定范围的联系始终受限。

## 4.4 Collaboration and Negotiation Network｜协作与协商网络

当个人已经拥有可信上下文、可表达的身份和明确的代理边界后，connectto 可以把这些能力向外连接：

- 用户表达当前事项后，Agent 在已有关系中寻找合适的人与直接或间接路径；
- 每位参与者通过自己的长期 Connector 或本次 Connection 专属的临时 Connector 私下表达意图、条件和披露许可；
- 各方 Connector 只交换本人允许用于当前 Connection 的最小上下文；
- 在授权范围内，Connector 可以持续试探、追问、协调和推进；
- 新的个人判断、扩大披露和重要承诺交还对应本人；
- 谁促成了连接、各方采取了什么行动以及最终结果如何，回到各自拥有的关系上下文。

私人关系档案不因进入网络而公开。网络扩大个人可发起和参与的协作范围；关系上下文、授权与连接结果继续由个人控制。

# 五、产品如何从关系工作走向持续协作

connectto 有四个进入时刻：

1. **会前准备**：用户需要恢复人物、关系、承诺和本次目标；
2. **真实交流之后**：新的理解、关系线索、条件和结果进入人物上下文；
3. **当前事项需要推进**：用户表达希望促成什么，并设定可接触范围、披露边界和授权方式；
4. **Connection 正在形成**：各方 Connector 私下交换意图和条件，在授权范围内持续协调。

这些入口进入同一条闭环：

1. 用户表达当前意图或记录一次真实交流；
2. connectto 按需理解人物、关系和本次边界；
3. 各方通过长期 Connector 或临时 Connector 私下表达意图、条件和披露许可；
4. Connector 在已经确认的范围内试探、追问和协调；
5. 出现新判断、扩大披露或新承诺时，Connector 询问对应本人；
6. 真实交流开始、条件被接受或各方明确结束后，结果更新人物、关系、身份与 Agent 判断；
7. 新的会前准备、真实交流或当前事项再次进入同一闭环。

# 六、为什么从真实关系切入

| 入口条件 | 对产品的意义 |
| --- | --- |
| 单个用户立即有价值 | 会前准备、交流记录和当前事项推进都不等待对方安装 |
| 上下文接受现实校正 | 身份和判断建立在真实交流、各方条件、披露许可与结果上，而不只依赖填写 |
| 每次使用可以复利 | 一次连接产生的理解，继续提高下一次准备、协调和判断质量 |
| 自然形成 Agent 内核 | 长期记忆、当前意图、触发条件、权限边界和结果反馈来自同一闭环 |
| 不依赖完整生态 | 未注册参与者可以通过本次 Connection 专属的临时 Connector 私密参与 |

connectto 当前要连续回答三个问题：

1. 用户如何用最低负担表达当前意图、关系范围和披露边界？
2. 每次真实交流产生的理解，如何成为个人长期拥有、可修正的上下文？
3. 各方 Connector 如何在各自授权范围内持续协商，并把新判断、披露和承诺交还对应本人？

# 八、公司最终会长成什么

长期来看，connectto 可能形成四类相互连接的产品与网络：

| 产品或网络 | 负责什么 | 长期价值 |

整体形态始终服务于个人：个人拥有关系上下文，决定如何被理解、如何被接近，以及谁可以代表自己做到哪一步。

# 十、当前聚焦

长期愿景可以宏大，当前产品围绕创业者和独立 BD 打磨一条完整关系工作链：

1. 用户在会前恢复人物、关系、承诺和本次目标；
2. 用户通过文字、语音或录音记录真实交流，持续更新人物与关系理解；
3. 用户用一句话表达当前意图，Connector 理解可接触范围、披露边界和授权方式；
4. 各方通过自己的长期 Connector 或本次 Connection 专属的临时 Connector 私下表达意图和条件；
5. Connector 在授权范围内试探、追问和协调，遇到新判断、扩大披露或新承诺时询问对应本人；
6. 真实交流开始、条件被接受或各方明确结束后，结果回到人物、关系和下一次工作。

当前产品用这条工作链建立长期所需的关系证据、身份理解、许可边界和结果反馈。页面布局、信息架构、视觉和 App 形态由产品同事继续定义，不作为长期骨架的一部分。
